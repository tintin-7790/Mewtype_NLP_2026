# Dense Evidence Retrieval 对照实验

本实验只评估 Dense 检索能否改善证据定位，不预设它优于原流程。所有病例必须为虚构、公开许可或已获授权资料，并在同一记录截止点截断。

## 三组设置

| 组别 | 流程 | Dense 检索 |
|---|---|---|
| A | `baseline` | 关闭 |
| B | `evidence_pipeline` | 关闭 |
| C | `evidence_pipeline` | 开启，固定 BGE-M3 服务、切分参数、Top-K 和阈值 |

三组必须使用同一病例集合、Qwen 服务与版本、生成参数、提示词版本、运行环境和评审标准。A/B/C 各自记录 Qwen 调用；C 另行记录 Embedding 调用、编码文本数和耗时。不要把本地 BGE-M3 的结果外推为赛方内网服务效果。

## 数据划分与标注

1. 开发集用于选择 `max_chunk_chars`、Top-K 和最低相似度；参数冻结后才运行保留测试集。
2. 每个关键陈述由人工建立允许的 `source_id` 和原文片段，并标注否定、时间、完成/进行中/计划状态。
3. 对同一事实构造否定、数值、时间和状态对照项；同一模板的变体必须放在同一数据分区，避免模板泄漏。
4. 合成病例可验证程序不变量与事实一致性；未经医学审核时不能作为诊疗正确性的金标准。

## 指标定义

- JSON 结构合规率：通过正式结构校验的病例数 / 病例总数（自动）。
- 关键事实完整率：输出覆盖人工关键事实数 / 关键事实总数（人工或专业审核）。
- 无依据生成率：无法由截止点内来源支持的事实陈述数 / 输出事实陈述数（人工或专业审核）。
- 否定、时序、计划状态错误率：对应错误数 / 对应可评估陈述数（规则初筛，人工复核）。
- Retrieval Recall@K：金标准来源片段出现在前 K 个候选的查询数 / 可检索查询总数；不得用相似度代替相关性标注。
- evidence 真实支持比例：引用来源确实支持陈述的 evidence 数 / evidence 总数（人工或专业审核）。
- 资源指标：Qwen 调用数、prompt/completion/total Token、Embedding 调用数、编码文本数、各服务耗时和总耗时。

每项同时报告分子、分母、比例及失败病例；不得丢弃超时、解析失败或无候选病例。模型自评和文本相似度只能作为辅助信号，不能替代医学评价。

## 冻结与复现记录

保存病例集版本、病例哈希、代码提交、提示词版本、Qwen/Embedding 实际模型标识、参数、随机种子、Top-K、阈值、切分长度、运行日志和人工标注版本。先在开发集冻结设置，再对保留集各运行一次 A/B/C；若远程服务无法逐字复现，如实记录，不挑选最好的一次输出。
